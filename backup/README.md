# Backup and restore

`capture.sh` runs on the **source** host and writes one tarball of the state
that `ansible/site.yml` cannot rebuild.

```bash
sudo ./backup/capture.sh /tmp/lycus-backup.tar.gz
```

It stops the gateway first so `state.db` — SQLite in WAL mode — is quiesced and
checkpointed rather than copied hot, and restarts it afterwards via an `EXIT`
trap.

## What it captures

`~/.hermes` (config, `state.db`, memories, skills, cron jobs), `~/.ssh`,
`~/.claude` and `~/.claude.json`, `~/.wireguard`, `~/.gitconfig`, `~/.config`,
`~/.azure`, `~/.docker`, `~/projects`, `~/resume-tailoring`.

## What it deliberately does not

Anything `site.yml` rebuilds: packages, toolchain, services. Plus three large
rebuildable caches — `~/.cache/ms-playwright` (~948 MB, regenerated by
`playwright install`), `~/.npm`, and `~/.vscode-server` (~6.4 GB). Together
those were most of why the old droplet's disk sat at 95%; carrying them across
would move the problem rather than solve it.

## Repositories

Most of `~/Development/claude` has git remotes and should be re-cloned rather
than copied. Four directories have **no remote** and exist nowhere else —
`acquire-tile-counter`, `home-assistant-debugging`, `secrets`, `smscpa`. Capture
those explicitly:

```bash
tar czf /tmp/lycus-repos.tar.gz -C ~/Development/claude \
  acquire-tile-counter home-assistant-debugging secrets smscpa
```

## Secrets

`~/.hermes/.env` and `~/.ssh` private keys are inside the tarball, so treat it
as a secret: transfer it over SSH, restore it, delete it. Values that Ansible
itself needs (the user environment file) belong in
`ansible/group_vars/all/vault.yml`, encrypted with ansible-vault — not in here.
